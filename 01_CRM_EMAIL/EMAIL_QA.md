# EMAIL_QA — приёмка CRM-макета Учи.ру

**Версия 0.1.** Использовать до передачи каждого макета. Фиксировать `PASS`, `FAIL`, `NEEDS_REVIEW`, `NOT_TESTED` отдельно для desktop и mobile, где это применимо.

## Проверки Figma-дизайна

- [ ] Аудитория (родители/учителя) и цветовой режим определены корректно.
- [ ] Использованы реальные CRM-компоненты/варианты, оригинальные логотипы и корректные текстовые стили.
- [ ] Цветовые токены применены по назначению слоя: текст, фон, кнопка, графика не перепутаны.
- [ ] Desktop 680 px; mobile 414 px; мобильные контентные боковые отступы 16 px.
- [ ] Хедер и футер присутствуют; при целевом действии предусмотрен CTA.
- [ ] Не более одного hero; соблюдён контентный ритм; нет повторяющихся блоков ради объёма.
- [ ] Основной CTA коралловый, по смыслу и визуально доминирует; вторичный CTA соответствует допустимому варианту.
- [ ] Мобильная компоновка перестроена в правильном порядке, без горизонтальной прокрутки, обрезки и накладок.
- [ ] Кнопки в mobile не растянуты произвольно; если две — они стоят вертикально, в правильном порядке.
- [ ] Шрифты, переносы и высоты текста не приводят к переполнению; применены существующие варианты.
- [ ] Проверено качество/кроп изображений, обтравка, отсутствие случайных белых плашек/артефактов.
- [ ] Текст, CTA, URL, даты, цифры, персонализация и обязательные дисклеймеры соответствуют согласованному ТЗ.
- [ ] Контраст и смысловая доступность проверены для светлой/предполагаемой тёмной темы; ключевые данные не спрятаны только в графике.
- [ ] Для изображений предусмотрены альтернативные тексты на этапе реализации.
- [ ] Исходные мастер-компоненты и существующие утверждённые письма не изменены.

## Проверки организации Figma

- [ ] Выбрана правильная аудитория и тематическая страница.
- [ ] Имя макета соблюдает локальный стандарт, включая `_` вместо пробелов внутри частей.
- [ ] Компонент `Status` заполнен и расположен **над** готовым письмом.
- [ ] Макет находится в корректном месяце **создания**, `Liner` не продублирован.
- [ ] На финальный desktop/mobile даны прямые ссылки.

## Технические проверки за пределами Figma

**Не засчитывать как PASS без реального HTML/ESP-теста:** верстка таблицами, fallback-шрифты, работа кнопок/ссылок, отображение в Gmail/Яндекс Почте/Mail.ru/VK Почте/Outlook, адаптация тёмной темы, блокировка изображений, alt в HTML, вес изображений/GIF, доступность и юридическая маркировка в отправленной версии.

## Формат отчёта

```
Аудитория: ...
Figma: ...
Desktop: PASS / FAIL / NEEDS_REVIEW
Mobile: PASS / FAIL / NEEDS_REVIEW
Tokens/components: ...
Content/CTA: ...
Status / Page / Liner: ...
Known issues: ...
HTML/client tests: NOT_TESTED (или ссылка на фактические результаты)
```
