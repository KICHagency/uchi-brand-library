# ИНСТРУКЦИЯ_SMM — AI + Figma

**Назначение:** пошаговый порядок создания постов и каруселей Учи.ру. Не переопределяет `00_CORE`.

## Входные данные
ТЗ (аудитория, тема, цель, текст, площадка, форматы, ссылки/CTA, набор обязательных утверждений, дедлайн), файл/страница для размещения, разрешённые изображения/иллюстрации. Для рекламы — требования конкретной площадки к выбранному placement.

## Алгоритм
1. Прочитать `00_CORE`, SMM-гайд, `02_SMM_DESIGN_SYSTEM.md`, `03_SMM_FORMATS_AND_RESIZE.md`, при необходимости `05_SMM_CHATBOT.md`.
2. Подключить Figma, проверить **учётную запись UCHI**, доступ чтения к гайду и библиотеки, доступ редактирования к *рабочему* файлу. Если нет прав — не объявлять задачу сделанной.
3. Определить аудиторию: **родители / учителя** (или явно согласованный иной сегмент), выбрать соответствующий режим цветовой системы. Не копировать подростковые цвета в учительскую палитру.
4. Определить тип: одиночный пост, карусель (обычно 4–6 карточек по ТЗ), Stories, рекламные адаптивы, материал чат-бота. Не смешивать PDF-методичку и SMM-карусель.
5. Подготовить *контентную архитектуру*: для карусели — обложка / одна мысль на следующий слайд / завершение или CTA; указать точный текст для каждого кадра. Не менять факты, цены, даты или цитаты без согласования.
6. Найти подходящие **компоненты и варианты** в актуальном гайде. Использовать инстансы и существующие компоненты (`Text-base-block`, карточки, логотипы, пагинация и др.), а не рисовать похожие элементы с нуля.
7. Для обычного квадратного поста использовать заданную сетку; параметры прочитать в `02_SMM_DESIGN_SYSTEM.md`. Отступы, типографика и лимиты должны выполняться до декоративной доработки.
8. Создать макеты **в отдельной рабочей зоне**. Исходные гайды, библиотеки, утверждённые макеты и мастер-компоненты не менять. Все тексты — редактируемые, графика — максимально редактируемая, фирменные токены — привязанные к роли.
9. Если требуется новый визуальный ассет — получить его по профильному фото/иллюстративному гайду; не подменять фирменную иллюстрацию произвольным AI-изображением.
10. Для карусели — проверить последовательность, ритм плотности, единый визуальный язык, наличие/корректность пагинации и различимость обложки.
11. Для Stories/Ads — **пересобрать композицию**, а не просто растянуть. Соблюдать безопасные зоны в конкретном placement и проверять фактические размеры.
12. Запустить `06_SMM_QA.md` и проверить результат скриншотами в Figma. Отдельно описать непроверенное.
13. Вернуть Figma-ссылку, список фреймов и размеров, использованные компоненты, ограничения и статус проверки.

## Допустимая самостоятельность
Можно предлагать модульную структуру и сокращение перегруженного текста **с маркировкой предложенных редакторских правок**. Нельзя молча менять утверждённые формулировки, обещания, ссылки, права партнёров или юридический текст.

## Стартовый запрос
> Изучи CORE и SMM-документы проекта. Проверь доступ к Figma. Создай [формат] для [аудитория] по ТЗ [вставить], используя утверждённые компоненты и шаблоны. Сначала определи структуру и сопоставь элементы с компонентами; после этого собери редактируемые фреймы в [рабочая Figma-ссылка]. Проверь каждый формат и отчитайся о соблюдении правил и обнаруженных ограничениях. Не меняй мастер-библиотеку.
