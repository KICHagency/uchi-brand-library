# SMM_FORMATS_AND_RESIZE

## Базовые форматы
| Формат | Размер | Статус |
| --- | --- | --- |
| Одиночный SMM-пост и кадр карусели | 1080×1080 | Базовый формат, подтверждён макетами |
| Вертикальные посты / адаптивы | 1080×1350 | Есть варианты в компонентах и рабочих файлах |
| Stories / вертикальные обложки | 1080×1920 | Есть варианты в компонентах и рабочих файлах |
| Горизонтальная графика | 1920×1080 | Есть в библиотеке и рабочих файлах |
| VK Ads, отдельные примеры | 1080×607; 600×600; 1080×1350 | Обнаружены в родительском рабочем файле |
| РСЯ, отдельные примеры | 1080×1080; 1920×1080; 600×600; 1080×1350 | Обнаружены в рабочих файлах |

**Внимание:** примеры размеров в Figma не заменяют актуальных требований VK Ads или Яндекс Директа к конкретному типу рекламы, плейсменту, файлу, весу и зонам интерфейса. При публикации сверять с текущей технической спецификацией кампании.

## Алгоритм ресайза
1. Зафиксировать главное сообщение, CTA, обязательные логотипы и факты; не прятать их при адаптации.
2. Выбрать компоненты с соответствующим `Format` или другой гайдовый вариант.
3. Сохранить типографическую иерархию, но заново скомпоновать блоки для вертикального/горизонтального формата.
4. Перекомпоновать иллюстрации, фотографии, маски и обтравки. Не растягивать фото и персонажей непропорционально.
5. Для Stories держать ключевые элементы вне UI-зон площадки; **точные безопасные поля взять из требований размещения**, не угадывать.
6. Для рекламы проверять ограничения по тексту, логотипам и интерфейсным оверлеям актуального плейсмента.
7. Проверить макеты в натуральном размере, уменьшенном превью и финальном экспорте.

## Карусель
Внутри одного набора кадры должны быть одинакового размера, если ТЗ не предусматривает иное. Обложка должна считываться отдельно; внутренние карточки распределяют контент по смыслу, а не по равному числу слов. Нумерация/пагинация — согласно выбранному компоненту. Иные, чем квадрат, размеры согласуются с требованиями канала.
